Problem

The route's data-orchestration and derivations (winningCaption, the #29-bound selectedCategory) are entangled with 200 lines of markup, so they are exercisable only by rendering the DOM.

Solution

One createJediFeed() module owns the four resources plus the derivations behind a small accessor interface; the route reads accessors and renders.

Wins

  • ▸ locality: feed logic in one module
  • ▸ leverage: derivations testable without DOM
  • ▸ route tests stop re-checking jedi-api data
  • ▸ the seam #29 filtering lands behind
  • ▸ unblocks Candidates 2 & 4
Aligns with ADR-0002 & ADR-0001. Selection/filtering stays deferred to #29 — this only names the seam it lands behind. The module lives in src/lib/jedi/ beside jedi-api: a within-front-end folder, not a package split.

Solution
