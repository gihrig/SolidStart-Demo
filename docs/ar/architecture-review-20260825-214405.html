Candidate 1

Type the feed envelope

Worth exploring ports & adapters · contract seam

backend/crates/services/web-server/src/web/routes_ws.rs · bindings/WsEvent.d.ts · frontend/src/lib/websocket.ts

Before — shallow envelope

WsEvent (wire)
event_type: string
channel: string
payload: unknown
websocket.ts
const msg = data.payload as ConvMsg;

Interface carries no invariant. The client casts, unchecked. A malformed payload passes for a Message.

After — deep envelope

WsEvent · tagged union
ConvMsg { payload: ConvMsg }
AgentUpdate
ConvUpdate
websocket.ts
case "conv_msg": e.payload // ConvMsg

The variant binds the payload type. The client narrows by discriminant. No cast.

Problem. The envelope is shallow — two strings and unknown hold the whole protocol; three live event types now share it (#85).

Solution. Make WsEvent a #[serde(tag="event_type")] enum; ts-rs exports a discriminated union.

  • leverage: payload type follows the discriminant
  • locality: the event-shape invariant lives in one enum
  • delete the unchecked as ConvMsg
  • three constructors can no longer mismatch the triple
Reopens ADR-0015 (Q7). That decision kept payload untyped when only conv_msg was live and two helpers were dead. #85 made all three live — one adapter became three. The union is now real, so the seam is worth reopening.

Give the routing key a Channel type

Worth exploring in-process

Before — the key is a string, spread out

After — one deep Channel

Conv(id) · Agents · Convs"]:::deep

One type parses, keys, and dispatches. The wire stays a string — no contract change.

Problem. No Channel type exists; the conv:{id} key and the kind set live as strings across two matches and three constructors.

Solution. A backend-internal Channel enum owns parse, key, and the authorize dispatch.

  • locality: one place to add a channel kind
  • compiler enforces exhaustiveness
  • delete two string matches
  • no contract change; CONTEXT.md already names Channel

Modest today — three kinds. It pays back the moment a fourth channel lands.

Candidate 3

Concentrate the mutation → poke rule

Speculative in-process

backend/crates/services/web-server/src/web/rpcs/conv_rpc.rs · rpcs/agent_rpc.rs

Before — every handler remembers

create_convbroadcast_conv_update()
update_convbroadcast_conv_update()
delete_convbroadcast_conv_update()
add_conv_msgbroadcast_conv_msg()
create/update/delete_agent×3

Seven manual pokes. The generated CRUD was bypassed to add them. A new mutation can forget.

After — one seam pokes

create · update · delete …
declare channel: convs
mutate-then-poke seam
write → poke(channel)

The poke rule lives once. The model stays free of the socket.

Problem. The rule "a mutation pokes its list feed" is enforced by memory at seven handlers, not by structure.

Solution. A mutate-then-poke seam at the RPC layer pairs each write with its poke; the model keeps no transport knowledge.

  • locality: the poke rule lives in one seam
  • a new mutation cannot forget
  • keeps the model ↔ transport seam intact
  • open question: exactly where the seam sits
Speculative. The friction is real; the seam placement is not obvious. This one is for the grilling loop, not the patch.

Top recommendation

Candidate 1 — Type the feed envelope

Freshest friction, and the only one that removes an unchecked cast at the seam both surfaces share. #85 turned a one-variant envelope into a real three-variant union, so the ADR-0015 choice to keep payload untyped no longer holds. Deepen the type; the client stops casting.

Lower-risk alternative: Candidate 2 — a Channel type is backend-internal and reopens no ADR.
