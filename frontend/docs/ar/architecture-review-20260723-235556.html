// MessagePanel.test.tsx:21-30 — the whole socket is stubbed out
vi.mock("~/lib/websocket", () => ({
  useWebSocket: vi.fn(() => ({ connected: () => false, subscribe: vi.fn(), onConvMsg: undefined, … })),

// so MessagePanel.tsx:16 listStale · :26-29 dedup · :61-67 unsubscribe-on-conv-change → no test through the interface
Two adapters justify the seam: a live socket in prod, an in-memory feed in tests. Today websocket.ts calls onMount(connect) per component — the seam is per-instance and there is no test adapter, so the trickiest reactive logic in the file is unreachable.
Problem

MessagePanel creates its socket internally; the only integration test replaces the whole module, so dedup and the listStale race guard cross no test seam.

Solution

Accept the feed as a dependency (a small port), pass a live adapter in prod and an in-memory one in tests.

  • Interface = test surface again
  • Race guards testable, deterministically
  • One shared socket, not one per panel

Problem

The bigint→Number precision decision leaks: the seam re-coerces at nine call sites and callers must still know ids are bigint. A module-global rpcId couples tests to hidden state.

Solution

Fix the id shape once inside the seam; scope rpcId to the client. Callers pass a domain id and forget precision.

  • Locality: coercion in one place
  • Callers drop bigint knowledge
  • Tests stop depending on a global

Top recommendation

B · Deepen the sidebar option seam

The strongest depth-for-effort trade. The selection-highlight-vs-focus-ring distinction is load-bearing in CONTEXT.md and already produced two bugs (#37, #38) — both because the paint decision is duplicated across three cards instead of owned by useListbox. Absorbing the option paint and the index↔id adapter into the seam turns three thin re-wirings into presentational cards, and moves the ring/highlight logic to one place that is tested once. Start here; A (delete accumulator) is a five-minute warm-up alongside it.
