Candidate C-07

Concentrate scheme identity behind one seam

✓ Shipped per ADR-0023 (#164). Typed SchemeName; get_scheme is total; the PwdParts codec moved to pwd/pwd_parts.rs. Public seam and ts-rs bindings unchanged.
Before — split identity

  • currency rule

  • wire format
    #{name}#{hash}

    PwdParts::from_str

After — one deep scheme module
hasher.rs — orchestrator
hash · validate · spawn_blocking
calls ↓ small interface
scheme (deep)
owns name ↔ impl
owns currency verdict
owns wire format + parse
status_for(name) → SchemeStatus
Problem

Scheme identity is split: SchemeStatus lives in dispatch.rs, but the "is it current?" verdict is decided in hasher.rs.

Solution

The scheme module owns the currency verdict and the name type; hasher.rs orchestrates only.

Wins
  • locality: scheme facts in one module
  • a new scheme touches one file
  • stringly-typed name can become a type
  • hasher shrinks to pure orchestration
Deletion test: weak leverage — one caller (validate_pwd). The win is locality, not reuse across N call sites.

Problem

Scheme01, Scheme02, and web_token each read auth_config() directly, so tests cannot pass their own key.

Solution

Pass the key into hash/validate and the token functions. The global stays the production caller only.

Wins
  • testability: interface is the test surface
  • tests need no process-wide env
  • two adapters: env in prod, literal in tests
  • kills the late .unwrap() panic risk
✗ Rejected — keep the rust10x canonical blueprint. The blueprint uses a global auth_config() singleton on purpose. Inverting it for the crypto leaves trades blueprint fidelity for a testability gain not wanted here. The global stays.
