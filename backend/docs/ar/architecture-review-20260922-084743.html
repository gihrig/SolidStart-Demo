The service keeps the seam; the Feed is a deep module in a lib.

Problem

The realtime Feed lives inline in the service binary. Login and RPC handlers delegate to lib-web; the Feed does not.

Solution

Move the Feed module to a lib. The service keeps routes() and the upgrade only.

Wins

  • locality: Feed logic + ~400 test lines in one module
  • leverage: the service interface shrinks to wiring
  • the interface is the test surface: authorize / broadcast_* tested without the service
  • contract seam uniform: Channel / WsEvent join the other exported types in a lib

⚠ Echoes ADR-0025 — worth reopening, not settled.

ADR-0025 rejected extracting the login flow (card C-14) because that handler is a line-for-line copy of the rust10x blueprint. This Feed is project-specific — its own lineage (ADR-0016 / 0018 / 0020, #85 / #106 / #109 / #115), not blueprint code — and issue #167 asks to “delegate to the libs.” Two cautions carry over from ADR-0025: the handler has one caller, and authorize is DB-bound. Verify rust10x ships no ws layer before committing.

C-17 · Co-locate the Poke rule

Worth exploring in-process

src/web/poke.rs · src/web/routes_ws.rs

Before — one rule, two files

markers: Convs · Agents · Conv

⇄ bounce
to read

routes_ws.rs

PokeReceipt<C>

new() private

markers Convs / Agents / Conv shadow the Channel variants — two vocabularies for the same channels.

After — one rule, one module

poke module

  • PokeReceipt<C> · mint stays private
  • PokedRpcResult<T,C>
  • markers beside the variants they mirror
broadcast_* → mint receipt — the invariant reads top-to-bottom.

Problem

One rule (ADR-0016) spans two files. PokeReceipt sits in routes_ws.rs; PokedRpcResult and the markers sit in poke.rs.

Solution

Put PokeReceipt, PokedRpcResult, and the markers in one poke module. Keep the mint private.

Wins

  • locality: the poke invariant sits in one module
  • no bounce between files to read one rule
  • the marker/variant shadow is visible in one place
  • the receipt mint stays private — ADR-0016 intact
Note: C-16 subsumes this. If the Feed moves to a lib, the poke types co-locate on the way.

C-18 · Curate the service’s public surface

Strong in-process

src/web/routes_ws.rs · src/web/mod.rs

Before — interface as wide as the crate

pub surface

  • routes() · WsState · broadcast_*
  • WsRouteState · broadcast()
  • PokeReceipt (pub)
  • pub mod poke/routes_*/rpcs

implementation

WsRouteState (3 refs) & raw broadcast (7 calls) — all in-file.

After — surface = what app.rs wires

pub surface

routes() · WsState · broadcast_*

implementation

WsRouteState · broadcast() · PokeReceipt
→ pub(crate) / private

Problem

The binary exports pub items nothing outside the crate reads. WsRouteState and the raw broadcast method are pub but used only in routes_ws.rs.

Solution

Narrow them. WsRouteState → private; broadcast → private. Keep WsState, routes(), broadcast_* public.

Wins

  • interface shrinks to what app.rs wires
  • a smaller seam — the crate hides its internals
  • follows C-13 (curate lib-web, shipped)
  • meets the #167 “curate the public surface” criterion
Watch: under -D warnings, a type in a still-pub item’s signature cannot be tightened (private_interfaces). Tighten the type only when its enclosing item is also narrowed. Run cgs check before done.

Top recommendation

Start with C-18 — curate the surface.

It is the issue’s explicit ask. It is provable and low-risk: WsRouteState and raw broadcast are read only in-file. It follows C-13, which shipped. It moves the acceptance criteria forward with no design debate.

Then grill C-16. It is the larger prize — the service stops owning a deep subsystem — but ADR-0025 just rejected a nearby extraction. That decision is the maintainer’s. C-17 rides along with C-16.
