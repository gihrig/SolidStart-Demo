Two targets make the seam real: Post and Caption.

Problem

A Like has no module. #122 built it for Posts only, so #123 must copy it for Captions.

Solution

One Like module per tier, generic over the Like target. A target bundles its like table, parent column, and parent check. The front-end Like state serves a list of targets, not one Post.

Wins

  • leverage: #123 adds a Caption target, not a copy
  • locality: one race fix, one Post check
  • the like-table + parent-column clump becomes one type
  • the interface is the test surface: one suite, two targets
  • a batched liked-read fits Top Captions

A view-model names a Channel and a handler. The Feed does the rest.

Problem

Each poked Channel costs about seven hand edits in two modules. No test reaches the Jedi dispatch branches.

Solution

A view-model gives the Feed a Channel and a handler as one Subscription, held for its reactive scope. The Feed routes by Channel key, replays on reconnect, and recovers a missed poke. Tests share one in-memory Feed adapter.

Wins

  • leverage: a new Channel needs no Feed edit
  • locality: reconnect recovery lives in one module
  • two adapters — WebSocket and in-memory — make the seam real
  • dispatch is tested once, at the Feed interface
  • five hand-made Feed fakes go
  • an over-cap subscribe surfaces in one place

A typo becomes a compile error; routing is proved once.

Problem

Each RPC's method name, params, and surface are typed by hand on both tiers. No test joins the two copies.

Solution

The back-end exports the RPC contract through ts-rs: method, surface, params, and result. One back-end test proves each method is routed on its surface. The front-end client takes its names and types from the export.

Wins

  • a method-name typo becomes a compile error
  • one routing test covers every method
  • interface: the surface stops being per-call knowledge
  • leverage: pass-through client members collapse
  • caps are exported once, not mirrored
