⏺ Here's a complete diagnosis:

  ---
  What's Missing / Broken

  1. Bug Fixed: RecvError::Lagged silently kills Tab 2's delivery (back-end)

  The original while let Ok(event) = rx.recv().await exits the loop on Lagged errors — when the 100-message broadcast
  buffer fills up before the send task processes it. This can happen under any modest load and silently stops forwarding
   messages to that tab. The fix above handles Lagged by logging a warning and continuing, and only breaks on Closed.

  2. Missing: Initial message load (front-end + back-end gap)

  MessagePanel calls setMessages([]) when a conversation is selected, but never fetches existing messages. Tab 2 always
  starts with an empty list. For new cross-tab messages to work this doesn't matter — but Tab 2 is blind to any history.

  To fix this you'd need:
  - A list_conv_msgs RPC method on the back-end (none exists yet — get_conv_msg is defined but list_conv_msgs is not in
  the router)
  - A convMsg.list(convId) call in backendRpc
  - A fetch in the createEffect in MessagePanel

  3. The actual cross-tab failure (most likely root cause)

  The Playwright test says "WebSocket broadcast confirmed" but that test only verified Tab 1 received an echo, not that
  Tab 2 actually displayed Tab 1's message. In a real browser two-tab test the broadcast chain is:

  Tab 1 RPC → add_conv_msg → ws_state.broadcast_conv_msg()
    → tx.send() → Tab 2's rx.recv() → sender.send(Text)
    → Tab 2 ws.onmessage → onConvMsg() → setMessages()

  The Lagged exit was the most concrete code-level gap. To confirm which step is actually failing, open DevTools →
  Network → WS in Tab 2 and watch for incoming frames when Tab 1 sends. If frames arrive but the UI doesn't update, the
  issue is in the JS callback. If no frames arrive, the server-side delivery is broken.

  4. Warning explained: unused broadcast_conv_update / broadcast_agent_update

  These methods are defined in WsState but never called anywhere. They would be needed if update_conv or update_agent
  RPC calls should also push real-time updates to other tabs — currently only add_conv_msg triggers a broadcast.
